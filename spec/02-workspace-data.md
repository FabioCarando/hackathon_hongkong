# 02 · Workspace and data

The demo runs on a fake but realistic finance workspace for **Harbour Lane Trading Ltd (海港貿易有限公司)**. It's generated by `scripts/generate_workspace.py` (deterministic, re-runnable) into `workspace/`. Never hand-edit `workspace/`. Change the generator and rerun it:

```bash
uv run --with openpyxl --with fpdf2 --with pymupdf python scripts/generate_workspace.py
```

## The company

- HK trading company, 18 staff. Imports electronic components from Shenzhen/Dongguan and resells to HK and SE Asia.
- Functional currency HKD, also RMB and USD. FY = calendar year. FX in `sheets/fx_rates.xlsx` (about USD 7.80, RMB 1.08).
- "Today" in the data = **2026-10-05**. The September close is in progress.
- People: **David Wong** (director, approves anything > HK$50,000), **Anna Chan** (finance manager), **Ken Lau** (accounts clerk).
- Company memory: `workspace/COMPANY.md` (profile, people, account codes, suppliers with known domains, policies, forecast assumptions).

### `sources.json` schema (per-cell provenance, used by the app too)

```json
{
  "file": "sheets/forecast_2027_2028.xlsx",
  "sheet": "Forecast",
  "cell": "C9:Z9",
  "value": 80000,
  "sources": [{"doc": "COMPANY.md", "page": null, "quote": "Rent assumed flat at HK$80,000 ..."}],
  "reason": "Rent held flat at current lease rate until the lease expiring 31 Dec 2026 is renewed.",
  "commit": "cbcb6ffbc58a36682d5b7eb00c22e4aa289e9e3b"
}
```

`cell` can be a single cell or a range. The app appends to this list on every accepted change and fills in `commit` after committing.

## Data rules

- Amounts in the register match the PDFs exactly. `amount_hkd = amount × fx_rate` of the invoice month.
- Held invoices are still written to the register with `status = "HELD"` so the document is traceable, but they are never `"Entered"` (payable) until a human approves. This matches `tasks[1]`.
- New register rows are appended after the last used row (row 19 onward).
